# Что такое триггер (TRIGGER) в SQL и когда его использовать?

## Ответ

Триггер — это функция, которая **автоматически выполняется** при `INSERT`, `UPDATE` или `DELETE` над таблицей:

```sql
CREATE TRIGGER set_updated_at
BEFORE UPDATE ON orders
FOR EACH ROW
EXECUTE FUNCTION update_timestamp();
```

Типичные сценарии:

- Автообновление поля `updated_at` при любом `UPDATE`
- Ведение аудит-лога (кто и когда изменил строку)
- Поддержание денормализованных данных в согласованном состоянии (например, пересчёт `total` в родительской таблице при изменении дочерних строк)
- Валидация данных, которую сложно выразить через `CHECK`

```sql
CREATE OR REPLACE FUNCTION update_timestamp()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

**Осторожно:** триггеры — это "невидимая" логика, скрытая от кода приложения. Злоупотребление ими усложняет отладку: разработчик видит простой `UPDATE`, но не видит, что он запустил каскад побочных эффектов в БД. На собеседованиях и в реальных проектах триггеры обычно рекомендуют использовать точечно, а бизнес-логику держать в коде приложения.
