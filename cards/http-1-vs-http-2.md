# Чем HTTP/2 отличается от HTTP/1.1?

## Ответ

| | HTTP/1.1 | HTTP/2 |
|---|---|---|
| Формат | Текстовый | Бинарный (фреймы) |
| Параллельные запросы | 1 запрос на соединение, браузер открывает ~6 TCP-соединений на домен | **Мультиплексирование** — много запросов в одном соединении |
| Заголовки | Отправляются целиком в каждом запросе | Сжимаются (**HPACK**) |
| Приоритизация | Нет | Есть (можно указать важность потока) |
| Server Push | Нет | Есть (на практике почти не используется) |

**Head-of-line blocking:** в HTTP/1.1, если один запрос "застрял", остальные в этом соединении ждут — приходится открывать новые TCP-соединения. HTTP/2 решает это на уровне HTTP мультиплексированием потоков в одном соединении.

```http
# HTTP/1.1 — заголовки текстом, каждый запрос отдельно
GET /style.css HTTP/1.1
Host: example.com

# HTTP/2 — бинарные фреймы, несколько запросов "переплетаются" в одном соединении
```

**HTTP/3** идёт дальше: работает поверх **QUIC** (UDP вместо TCP), что убирает head-of-line blocking уже на уровне транспорта — потеря одного пакета не блокирует остальные потоки.
