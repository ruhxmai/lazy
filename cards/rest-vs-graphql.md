# Чем REST отличается от GraphQL?

## Ответ

**REST** — набор соглашений: у каждого ресурса свой URL, сервер решает, какие поля вернуть.

```http
GET /api/users/42          → всё, что сервер решил вернуть про юзера
GET /api/users/42/orders   → отдельный запрос для заказов
```

**GraphQL** — один эндпоинт, клиент сам описывает нужные поля в одном запросе:

```graphql
POST /graphql
{
  user(id: 42) {
    name
    orders { total }
  }
}
```

| | REST | GraphQL |
|---|---|---|
| Эндпоинты | Много (`/users`, `/orders`, ...) | Один (`/graphql`) |
| Over-fetching (лишние поля в ответе) | Часто | Нет — клиент запрашивает только нужное |
| Under-fetching (нужно несколько запросов) | Часто | Нет — связанные данные одним запросом |
| Кэширование по HTTP | Простое (по URL) | Сложнее (один URL для всех запросов) |
| Порог входа | Ниже | Выше (схема, resolvers) |

**Важный нюанс:** GraphQL решает over/under-fetching, но может незаметно создать свою версию проблемы **N+1** — когда resolver для каждого вложенного поля отдельно стучится в базу данных вместо одного batched-запроса.

**Когда что выбрать:** REST — для простых CRUD-API с предсказуемой структурой. GraphQL — когда разным клиентам (веб, мобильное приложение, партнёры) нужны сильно разные наборы полей с одних и тех же ресурсов.
